# 出力仕様

statusline-macos.sh (macOS 版) と statusline-linux.sh (Linux 版) が満たす、外から観測できる出力の仕様をまとめる。両版は同じ入力に対して**同一の出力**を返す。実装上の理由や過去に採らなかった案は [DESIGN.md](./DESIGN.md)、テストの書き方は [tests/README.md](../tests/README.md) を参照。

出力を変える変更では、本書と `tests/assertions/` の期待値を同じ変更の中で更新する。

## 入力

Claude Code から stdin で渡される JSON のうち、次のフィールドを使う。

| フィールド | 用途 | 欠落時 |
| --- | --- | --- |
| `model.display_name` | モデル名と色 | `Unknown` として扱う |
| `effort.level` | 推論強度 (effort) と色 | effort を表示しない |
| `context_window.used_percentage` | コンテキスト使用率 | ctx を `· --` と表示 |
| `rate_limits.five_hour.used_percentage` | レートリミット使用率 | rate を `<チャート> --` と表示 |
| `rate_limits.five_hour.resets_at` | リセット時刻 (epoch 秒) | 時刻を表示しない (`0` と同じ) |
| `session_name` | セッション名 | セッション列を省略 |
| `workspace.current_dir` | ディレクトリ名とブランチ取得 | ディレクトリ列とブランチ列を省略 |

- 文字列フィールド (`model.display_name` / `session_name` / `workspace.current_dir` / `effort.level`) に含まれる制御文字 (改行･タブ･CR･ESC など) は半角スペースに置き換える。値に紛れた ANSI エスケープで後続の列の色が変わるのを防ぐ
- 値は加工せずそのまま出力する (`-n` で始まるセッション名なども文字どおり表示する)
- `pr` フィールドは使わない ([理由](DESIGN.md#stdin-の-pr-フィールド))。PR の状態は [`PR_STATUS=1`](#pr-の状態-pr_status1) のとき `gh` で自前に取得する

## 出力構造

出力は **2 行構成**。

```text
<directory> | <branch><ab><diff><pr> | <session_name>
✻ <model>∙<effort> <ctx> | <rate>
```

上は既定のレイアウトでの並び。各行の並び順は [レイアウト](#レイアウト-layout_line1--layout_line2) で変えられる。`<pr>` は `PR_STATUS=1` のときだけ出る。

### 区切り

| 位置 | 区切り |
| --- | --- |
| 列と列の間 (両行共通) | ` \| ` (スペース･パイプ･スペース) |
| `<model>` と `<effort>` の間 | `∙` (U+2219、前後スペースなし、無色) |
| `<effort>` (または `<model>`) と `<ctx>` の間 | 半角スペース 1 個 (パイプは出さない) |
| ブランチ名と `<ab>`、`<ab>` と `<diff>` の間 | 半角スペース 1 個 (空の要素の前には置かない) |
| `<diff>` と `<pr>` の間 | 半角スペース 1 個 (`<pr>` が空なら置かない) |

### 1 行目

- 既定の並びは `directory` → `branch` → `session`
- 値が空の列は**列ごと省略**し、区切りも出さない
- すべての列が空のときは**1 行目ごと出さない**。改行も出さず、出力は 2 行目だけの 1 行になる
- 改行は 1 行目の末尾に付く。1 行目が無いときに出力の先頭へ空行が出ることはない

### 2 行目

- 既定の並びは `model_ctx` → `rate`
- **常に出力する**。`model_ctx` と `rate` の両方が必ず含まれる
- `session_name` は 2 行目には置かない

## 1 行目の要素

### directory

`workspace.current_dir` の basename。

- 末尾の `/` を取り除いてから basename を取る (`/tmp/my-project/` → `my-project`)
- `current_dir` が `/` または空のときは basename が空になり、列ごと省略する
- 25 文字でトリムする ([トリム規則](#トリム規則))
- 無色 (端末と Claude Code の前景色)
- `SHOW_CWD=0` のときは表示しない。2 行構成と他の 1 行目要素はそのまま残る
- 取得に git は使わない

### branch 列

`<ブランチ名>[ <ab>] <diff>[ <pr>]` を 1 つの列として出す。

ブランチ名:

- `workspace.current_dir` で `git branch --show-current` を実行した結果
- 結果が空 (detached HEAD) のときは `git rev-parse --short HEAD` の短縮 sha を使う
- git 外、`current_dir` が空、git が未インストールのときは**列ごと省略**する (`<ab>`、`<diff>`、`<pr>` も出ない)
- 25 文字でトリムする。`/` を含み末尾のセグメント (最後の `/` より後ろ) が 22 文字以下なら、末尾を残して中間を省略する ([トリム規則](#トリム規則))
- `<ab>`、`<diff>`、`<pr>` はトリムの対象外で、ブランチ名が切れても残る

#### ahead/behind (`<ab>`)

ブランチ名の右、`<diff>` の左に置く。`git rev-list --left-right --count '@{upstream}...HEAD'` の結果から求め、ネットワークにはアクセスしない (直近の fetch/pull 時点の差になる)。

| 状態 | 表示 | 色 |
| --- | --- | --- |
| ahead のみ (push 待ち) | `↑N` | `professionalBlue` (`106;155;204`、light も同じ) |
| behind のみ (pull 待ち) | `↓M` | `warning` (dark `255;193;7` / light `150;108;30`) |
| 両方あり | `↑N↓M` (ahead が先、区切りなし) | ahead と behind をそれぞれの色で塗る |
| 同期済み (ahead=behind=0) | 何も出さない | — |
| upstream 未設定 (rev-list が失敗) | `*` | `professionalBlue` (青) |
| detached HEAD (rev-list が失敗) | `*` | 無色 (前景色) |

- `↑` は U+2191、`↓` は U+2193、`*` は ASCII の U+002A
- ブランチ名は取れるが別の理由で rev-list が失敗する場合も、upstream 未設定と同じ青 `*` になる
- ahead に緑は使わない (隣の `<diff>` の `+add` と同じ色になるため)

#### 変更行数 (`<diff>`)

`<ファイル数><+追加><-削除>` を区切りなしで詰めて出す (例 `3+13-5` = 3 ファイル、+13 行、-5 行)。

| 項目 | 仕様 |
| --- | --- |
| 追跡ファイル | `git diff HEAD --numstat` (ステージ済み + 未ステージ) |
| 未追跡ファイル | `git status -z` の `??` エントリ。各ファイルの全行を `+` に加算する (`.gitignore` 対象は含まれない) |
| 未追跡の行数取得の上限 | 50 件 (`UNTRACKED_DIFF_LIMIT`)。51 件目以降はファイル数にだけ数え、行数は加算しない |
| バイナリファイル | ファイル数には数えるが、行数には加算しない |
| ファイル数の色 | `text` (`COLOR_SCHEME` に応じた固定色。dark 白 `255;255;255` / light 黒 `0;0;0`。デフォルトの前景色ではない) |
| `+N` の色 | `success` (緑) |
| `-N` の色 | `error` (赤) |
| 片方が 0 | その側を省略する (`3+8`、`2-5`)。ファイル数は変更があれば常に出す |
| すべて 0 (クリーン) | `·` (U+00B7、無色) |

#### PR の状態 (`<pr>`)

現在のブランチに紐付く GitHub の PR を `#<番号>[<CI記号>][ <件数>]` で、`<diff>` の右に半角スペース区切りで出す (例 `main ↑1 3+10-2 #12✓ 3`)。`PR_STATUS=1` のときだけ表示する。詳細は [PR の状態 (`PR_STATUS=1`)](#pr-の状態-pr_status1)。

### session_name

- `session_name` の値をそのまま出す。空なら列ごと省略する
- 40 文字でトリムする
- 既定のレイアウトでは 1 行目の末尾に置く

## 2 行目の要素

### model_ctx

`✻ <model>∙<effort> <ctx>` を 1 つの列として出す。

#### model

- `✻` (U+273B) とモデル名をスペース 1 個で結び、まとめてモデル色で塗る
- モデル名は 13 文字でトリムする。色の判定はトリム前の全文で行う
- `SHOW_MODEL_NAME=0` のときはモデル名を出さず、`✻` だけをモデル色で塗って出す。`✻` は設定によらず常に表示する

#### effort

- `effort.level` の値をそのまま出す (`low` / `medium` / `high` / `xhigh` / `max`)。トリムしない
- model とは別に、effort の語句だけを effort 色で塗る
- `SHOW_MODEL_NAME=1` のときは `<model>` との間に無色の `∙` を置く (前後スペースなし)
- `SHOW_MODEL_NAME=0` のときは `∙` を置かず、`✻` との間をスペース 1 個にする (`✻ high`)
- `effort.level` が無いときは `∙` も effort も出さない (`✻ <model> <ctx>`)
- 上記以外の値はそのまま無色で出す

#### ctx

現在の使用率を 1 文字のスパークで表す。履歴は持たない。

| 使用率 | 表示 |
| --- | --- |
| 70% 以上 | `<spark> NN%` を使用率の色で塗る |
| 70% 未満 | `<spark>` のみ (数値なし、無色) |
| 欠落 | `· --` |

- `<spark>` は `▁▂▃▄▅▆▇█` の 8 階調のうち 1 文字。使用率 p に対して `int(p / 100 × 8 + 0.5)` を 1〜8 に収め、その段の文字を使う
- `NN` と色の判定には、使用率を整数に丸めた値を使う

### rate

5 時間レートリミットの**残量** (100 − 使用率を整数に丸めた値) を表す。チャートは 6 文字 (`HISTORY_LEN`)。

| 残量 | `resets_at` > 0 | `resets_at` が 0 または欠落 |
| --- | --- | --- |
| 40% 超 (無色) | `<chart> HH:MM` | `<chart>` |
| 40% 以下 (色あり) | `<chart> NN% - HH:MM` | `<chart> NN%` |

- 数値 `NN%` は色が付くときだけ表示する
- 数値と時刻の区切りは ` - ` (スペース･ハイフン･スペース)。括弧 `()` は使わない
- 色が付くときは `<chart>` から末尾までをまとめて残量の色で塗る
- `HH:MM` は `resets_at` をローカル時刻に変換した値
- 使用率が欠落しているときは `<chart> --` (無色)。このときチャートの右端は現在値に差し替えない

チャート:

- 右端の 1 文字は**常に現在の残量**のスパーク。サンプリング間隔とは独立に、毎回の描画で最新値を反映する
- 左の 5 文字は [レートリミット履歴](#レートリミット履歴) の遷移を表す
- 履歴が 6 件に満たないときは左側を `·` (U+00B7) で埋める
- 履歴を保存できない (`HISTORY_DIR` が無効) ときも、`·····` の右に現在値の 1 文字を出す (例 `·····▁ 10% - 22:13`)

### 出力例

```text
my-project | main ↑2↓3 3+13-5 | my-session
✻ Opus 4.7∙high ▆ 72% | ▇▆▅▄▃▃ 35% - 18:30
```

```text
✻ Unknown · -- | ······ --
```

2 つ目は、rate 履歴が無い状態で空の JSON (`{}`) を渡したときの出力 (履歴があればチャート部分は保存済みの履歴になる)。1 行目の要素がすべて空なので 1 行だけになる。

## トリム規則

| 要素 | 上限 | 超過時 |
| --- | --- | --- |
| モデル名 | 13 文字 | 先頭 12 文字 + `…` |
| ブランチ名 | 25 文字 | 下記 |
| セッション名 | 40 文字 | 先頭 39 文字 + `…` |
| ディレクトリ名 | 25 文字 | 先頭 24 文字 + `…` |

ブランチ名は上から順に判断する。

| 条件 | 結果 | 例 |
| --- | --- | --- |
| 25 文字以下 | そのまま | `feature/new` |
| `/` を含み、最後の `/` より後ろが 22 文字以下 | 先頭 `25 - 1 - len("/<末尾>")` 文字 + `…` + `/<末尾>` | `feature/aaaaaaaaaaaaaaaaaaaa/yyy` → `feature/aaaaaaaaaaaa…/yyy` |
| それ以外 (`/` が無い、末尾が 23 文字以上) | 先頭 24 文字 + `…` | `feature/improve-awesome-statusline` → `feature/improve-awesome-…` |

- 22 文字は、先頭を最低 1 文字残せる上限 (`1 + "…" + "/" + 22 = 25`)
- 先頭を切った位置が `/` の直後でも、そのまま `…` を続ける (`feature/…/yyy` のようになりうる)
- detached HEAD の短縮 sha は `/` を含まないので中間省略にはならない。`core.abbrev` を大きくして 25 文字を超えたときは先頭 24 文字 + `…` になる

共通:

- `…` は U+2026
- 文字数は両版とも `LC_ALL=C.UTF-8` 下の文字単位で数える。CJK 文字も 1 文字として数える
- 表示幅 (CJK が 2 桁を占めること) は考慮しない
- effort、`<ab>`、`<diff>` はトリムしない

## 色

色は Claude Code の light/dark テーマに合わせた配色を使う。`COLOR_SCHEME` で `dark` (既定) と `light` を切り替える。`light` 以外の値はすべて `dark` として扱う。

色はすべて truecolor の前景色 (`\033[38;2;R;G;Bm`) で、色付きの区間の末尾には `\033[0m` が付く。

色を付けるのは、意図して色を指定する箇所 (下の表のうち色が｢無色｣でない行) だけで、それ以外の要素は無色にして端末と Claude Code の前景色に任せる。

### 色の閾値

RGB は dark の値。light の値は [セマンティックカラー](#セマンティックカラー) を参照。

| 指標 | 条件 | キー | dark の ANSI |
| --- | --- | --- | --- |
| ctx | 90% 以上 | `error` + 点滅 | `\033[5m\033[38;2;255;107;128m` |
| | 80% 以上 | `claude` (橙) | `\033[38;2;215;119;87m` |
| | 70% 以上 | `warning` (黄) | `\033[38;2;255;193;7m` |
| | 70% 未満 | 無色 | — |
| rate 残量 | 5% 以下 | `error` + 点滅 | `\033[5m\033[38;2;255;107;128m` |

| pr `#<番号>` | open + approved | `success` (緑) | `\033[38;2;78;186;101m` |
| | open + pending | `permission` (青紫) | `\033[38;2;177;185;249m` |
| | open + changes requested | `error` (赤) | `\033[38;2;255;107;128m` |
| | draft | 無色 | — |
| | merged | `merged` (紫) + 取り消し線 | `\033[4;9m\033[38;2;135;0;255m` |
| | closed | 無色 + 取り消し線 | `\033[4;9m` |
| pr CI 記号 | `✓` | `success` (緑) | `\033[38;2;78;186;101m` |
| | `✗` | `error` (赤) | `\033[38;2;255;107;128m` |
| | `●` | `warning` (黄) | `\033[38;2;255;193;7m` |
| pr コメントの件数 | — | 無色 | — |

- pr `#<番号>` は状態によらず下線 (`\033[4m`) を付ける。上表の色の ESC の前に置く (merged / closed は取り消し線と合わせて `\033[4;9m`)

- ctx と rate は警戒 (黄) → 危険 (橙) → 致命 (赤 + 点滅) の 3 段階。致命段は点滅属性 (`\033[5m`) で危険段と区別する
- model の判定は部分一致で、`Fable` → `Opus` → `Haiku` の順に評価する。バージョン表記に依存しない (`Fable 5 (1M context)` も紫)
- ultracode は入力上 `xhigh` と区別できないため、`xhigh` と同じ紫になる
- `max` のレインボーは effort の語句だけに掛かり、`∙` には掛からない

## レートリミット履歴

レートリミットの残量だけを履歴に持つ (ctx は持たない)。

| 定数 | 値 | 用途 | 変更 |
| --- | --- | --- | --- |
| `HISTORY_LEN` | `6` | チャートの文字数 | 不可 (conf に書いても無視される) |
| `POLL_INTERVAL_SEC` | `480` | 履歴に追記する最小間隔 (秒) | conf で可 (60〜3000) |
| `LOCK_TIMEOUT_SEC` | `2` | 履歴ファイルのロック待機上限 (秒) | 不可 |

- 履歴は全セッション共通の 1 ファイル (`<HISTORY_DIR>/rate`) に保存する
- 初回は現在値で 6 件を埋める。以降は前回の追記から `POLL_INTERVAL_SEC` 秒以上経っていれば 1 件追記し、末尾 6 件だけを残す
- ロックを `LOCK_TIMEOUT_SEC` 秒以内に取れなかったときは、その回の追記を行わない (描画は続ける)
- `HISTORY_DIR` の既定は `/tmp/claude-statusline-<uid>/`。env `CLAUDE_STATUSLINE_HISTORY_DIR` で変えられる (conf の対象外)
- `HISTORY_DIR` が symlink、自分の uid の所有でない、mode が 700 でない、のいずれかに当たると履歴機能を無効にして描画を続ける

### 間引き間隔の推奨レンジ

`POLL_INTERVAL_SEC` と `GIT_FETCH_INTERVAL_SEC` は env の上書き口を持たず、conf で変える。範囲外の値は起動時に丸められ、警告は出さない。

| 値 | 扱い |
| --- | --- |
| 空、数字以外を含む (負値を含む) | 既定値 (`480` / `900`) |
| 9 桁以上の数字 | 上限 |
| 下限未満 (`0` を含む) | 下限 (`60`) |
| 上限超 | 上限 |

| 定数 | レンジ | 下限の根拠 | 上限の根拠 |
| --- | --- | --- | --- |
| `POLL_INTERVAL_SEC` | 60〜3000 | statusline は数秒〜十数秒間隔で呼ばれるため、これより短いと毎回履歴が更新され間引きの意味がなくなる | 5 時間 (18000 秒) のウィンドウを 6 サンプルで覆うには 18000 ÷ 6 = 3000 秒が上限。超えるとチャートが傾向を示さない |
| `GIT_FETCH_INTERVAL_SEC` | 60〜1800 | これより短いと `git fetch` の子プロセスが頻発する。間引きは cwd 単位なので、同じリポジトリを複数の worktree で開くほど fetch の総数は増える | 30 分を超えると `↓behind` の自動更新が遅く、手動 fetch と大差なくなる |

### 優先順位と設定ファイル

優先順位は **env (`CLAUDE_STATUSLINE_*`) > 設定ファイル > 既定値**。env と設定ファイルの値が空文字のときは、指定されていないものとして扱う。

設定ファイル:

- 既定のパスは `~/.claude/statusline.conf`。env `CLAUDE_STATUSLINE_CONFIG` で差し替えられる
- シェルスクリプトとして読み込む (`.` で source)。短縮名 (`COLOR_SCHEME=light` 等) を変数代入で書く
- 通常のファイルで、かつ読めるときだけ読み込む。それ以外 (存在しない･権限が無い･ディレクトリ) は黙って無視する
- 読み込み前に上表の短縮名 9 つを未設定に戻すため、外の環境に同名の変数があっても影響しない
- 読み込み後、9 つの値の末尾の `\r` を取り除く (CRLF で保存したファイルでも同じ結果になる)
- `HISTORY_LEN` などの内部定数は、書いても読み込み後に定義し直されるため効かない
- 間引き間隔は読み込み後に [丸め](#間引き間隔の推奨レンジ) を適用する

配布テンプレート [`statusline.conf`](../statusline.conf) は全項目を既定値で記載している。

### レイアウト (`LAYOUT_LINE1` / `LAYOUT_LINE2`)

トークンを `|` で区切って並べる。トークン同士は常に ` | ` で結合する。

| 行 | トークン | 内容 |
| --- | --- | --- |
| 1 行目 | `directory` | ディレクトリ名 |
| | `branch` | `<ブランチ名>[ <ab>] <diff>[ <pr>]` |
| | `session` | セッション名 |
| 2 行目 | `model_ctx` | `✻ <model>∙<effort> <ctx>` |
| | `rate` | レートリミット |

共通:

- トークン前後の空白 (スペース･タブ) は無視する
- その行で使えないトークン (未知のもの、他方の行のもの) は無視する
- 同じトークンが複数回あるときは最初の 1 回だけ採る
- 値が空文字のときは既定値を使う
- 1 トークンに束ねた要素 (`model` と `ctx`、ブランチ名と `<ab>`･`<diff>`･`<pr>`) は個別に並べ替えられない

1 行目:

- 書かなかったトークンは出さない
- 値が空のトークンは列ごと省略する
- 有効なトークンが 1 つも無い、またはすべて空のときは 1 行目を出さない (例 `LAYOUT_LINE1="none"`)
- `SHOW_CWD=0` は `directory` を書かなかったのと同じ結果になる

2 行目:

- 変えられるのは `model_ctx` と `rate` の順番だけ
- 書かなかったトークンは既定の順で末尾に補う。`LAYOUT_LINE2="rate"` は `rate | model_ctx` になる
- 値が空でも列を省略しない

## バックグラウンド fetch (`GIT_FETCH=1`)

`GIT_FETCH=1` のときだけ、`↓behind` を最新に近づけるために `git fetch --quiet` をバックグラウンドで起動する。`GIT_FETCH=0` (既定) では fetch を一切行わず、ネットワークにアクセスしない。

- 描画は fetch の完了を待たない。fetch の結果は次回以降の描画の `<ab>` に反映される
- 前回の起動から `GIT_FETCH_INTERVAL_SEC` 秒未満なら起動しない。間隔は `workspace.current_dir` ごとに数える (同じリポジトリでもサブディレクトリや worktree が違えば別に数える)
- 次のときは起動しない: ブランチが取れない (git 外)、detached HEAD、upstream 未設定、`HISTORY_DIR` が無効
- 認証の入力を求めない (`GIT_TERMINAL_PROMPT=0`、`GIT_ASKPASS=/bin/true`、`SSH_ASKPASS=/bin/true`、`SSH_ASKPASS_REQUIRE=force`)。資格情報が無いリモートでは fetch は静かに失敗し、`↓behind` は更新されない
- fetch 自身の出力は捨て、statusline には混ざらない。`GIT_FETCH` による違いは、更新されたリモート追跡ブランチが次回以降の `<ab>` に反映されることだけ

## PR の状態 (`PR_STATUS=1`)

`PR_STATUS=1` のときだけ、現在のブランチに紐付く GitHub の PR を branch 列の `<pr>` に表示する。情報は `gh api graphql` をバックグラウンドで起動して取得し、描画はキャッシュを読むだけにする。

- `PR_STATUS=0` (既定) では `gh` を一切起動せず、ネットワークにもアクセスしない
- `PR_STATUS=1` でも、`LAYOUT_LINE1` に `branch` が無ければ `gh` を起動しない
- 値が空のときは `<pr>` も前のスペースも出さない。branch 列そのものは残る
- 環境変数 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` は見ない。設定されていても取得する

### 表示形式

```text
#<番号>[<CI記号>][ <件数>]
```

| 状態 | `#<番号>` の色 | 装飾 | CI 記号 | コメントの件数 |
| --- | --- | --- | --- | --- |
| open: approved | `success` | 下線 (SGR 4) | 表示する | 表示する |
| open: pending (レビュー待ち、またはレビューがまだない) | `permission` | 下線 (SGR 4) | 表示する | 表示する |
| open: changes requested | `error` | 下線 (SGR 4) | 表示する | 表示する |
| draft | 無色 | 下線 (SGR 4) | 表示する | 表示する |
| merged | `merged` | 下線 + 取り消し線 (SGR 4;9) | 出さない | 出さない |
| closed (マージされずに閉じた) | 無色 | 下線 + 取り消し線 (SGR 4;9) | 出さない | 出さない |

- `PR` という接頭辞は付けない (`#12`)
- 色は既存の色定義 ([セマンティックカラー](#セマンティックカラー)) の値を使う。draft と closed は色を付けず、端末の前景色に任せる。装飾は `\033[4m` (merged / closed は `\033[4;9m`) を色の前に置き、`\033[0m` で解除する。装飾は `#<番号>` だけに掛かり、CI 記号とコメントの件数には掛からない
- CI 記号は `#<番号>` の直後に区切りなしで続ける (`#12✓`)
- `<pr>` はトリムしない

レビュー状態は `reviewDecision` で決める。`reviewDecision` はレビューが必須でないリポジトリでは approve 済みでも常に `null` になるため、`null` のときは `latestReviews` (レビュアーごとの最新のレビュー) から決める。

| `reviewDecision` | `latestReviews` | レビュー状態 |
| --- | --- | --- |
| `APPROVED` | (見ない) | approved |
| `CHANGES_REQUESTED` | (見ない) | changes requested |
| `REVIEW_REQUIRED` | (見ない) | pending |
| 上記以外 (`null` など) | `CHANGES_REQUESTED` が 1 件でもある | changes requested |
| | 上に当たらず、`APPROVED` が 1 件でもある | approved |
| | どちらもない | pending |

CI 記号は、PR の head コミットの `statusCheckRollup.state` (GitHub が全チェックを集約した値で、PR 画面のチェック表示と同じもの) から決める。

| `statusCheckRollup.state` | 記号 | 色 |
| --- | --- | --- |
| `SUCCESS` | `✓` | `success` |
| `FAILURE` / `ERROR` | `✗` | `error` |
| `PENDING` / `EXPECTED` | `●` | `warning` |
| `null` (チェックが 1 つもない) など | 出さない | — |

コメントの件数:

- PR の `totalCommentsCount` (GitHub が数えたコメントの件数) をそのまま使う。GitHub の PR 一覧で吹き出しアイコンに出る数と同じ値で、次を合わせたもの
  - 会話タブのコメント
  - コードの行に付いたコメント (スレッドへの返信を含む)
  - 本文付きのレビュー
- 数え方は GitHub に任せ、投稿者による絞り込みや数え直しはしない
- 記号は付けず、数字だけを半角スペース 1 個の後に出す。CI 記号があればその後ろ (`#12✓ 3`)、なければ番号の後ろ (`#12 3`)。詰めると、CI 記号がないときに番号と続けて読めてしまう (`#123`)
- 件数が 0 のときは、件数も前のスペースも出さない (`#12✓`)。`99+` のような丸めはせず、そのまま出す
- 無色

リンク:

- `#<番号>` の部分 (色と装飾を含む) だけを OSC 8 で囲み、PR の URL へのリンクにする (`\033]8;;<url>\a` … `\033]8;;\a`)。CI 記号とコメントの件数はリンクに含めない
- 環境変数 `FORCE_HYPERLINK` が `0` のときは OSC 8 を出さない
- OSC 8 に対応していない端末ではクリックできない

### 対象の PR

- 問い合わせ先 (base リポジトリ) は `gh` 自身の解決に任せる (`gh api` の `{owner}` / `{repo}`)
- head のブランチ名とオーナーは push 先から決める
  - ブランチ名: `git rev-parse --abbrev-ref '@{push}'` の `<remote>/<branch>` の `<branch>`
  - オーナー: `git remote get-url --push <remote>` の URL (`git@host:owner/repo.git`、`https://host/owner/repo(.git)`、`ssh://git@host/owner/repo`) の `<owner>`
- push 先が取れない (まだ push していない) ときは、ローカルのブランチ名と base リポジトリのオーナーを使う。URL からオーナーを取れないときも base リポジトリのオーナーを使う
- head のブランチ名で新しい順に 10 件を取り、`headRepositoryOwner` が head のオーナーと一致するもの (大文字小文字は区別しない) だけを候補にして、次の順で選ぶ
  1. `OPEN` のうち最も新しいもの
  2. なければ、`headRefOid` がローカルの HEAD と一致する `MERGED` / `CLOSED` のうち最も新しいもの
  3. どちらもなければ PR なし

### 表示しないとき

次のいずれかに当たるときは `<pr>` を空として扱う。

- ブランチが取れない (git 外)、または detached HEAD
- キャッシュがまだない (ブランチを切り替えた直後の 1 回目の描画など)
- PR がない
- 最後に取得に成功してから `PR_STALE_SEC` (1800 秒) を超えた。`gh` の未認証、オフライン、GitHub 以外のリモート、base リポジトリが決まらない、などで取得に失敗し続けるとこれに当たる
- キャッシュの取得時刻が現在より未来 (時計が戻った後など)。次の取得の結果で置き換わる
- キャッシュが壊れている (フィールドの数、`fetched_at`、番号、状態のいずれかが不正)
- `HISTORY_DIR` が無効
- `gh` がインストールされていない

`gh` を案内するメッセージは出さない。キャッシュのうち番号と状態以外のフィールドが想定外の値のときは、そのフィールドがないものとして扱う (レビュー状態は pending、CI 記号とコメントの件数は出さない)。コメントの件数は、番号と同じく先頭が 0 でない 9 桁以内の整数のときだけ使う。URL が `https://` で始まらないか、URL に使う ASCII の英数字と記号 (`._~:/?#=&+@%-`) 以外の文字を含むときは、リンクにしない。

### 更新

- 描画時はキャッシュを読むだけで、`gh` も追加の `git` も呼ばない
- キャッシュは `workspace.current_dir` とローカルのブランチ名の組ごとに持つ (`<HISTORY_DIR>/pr-<key>`)。ブランチを切り替えると別のキャッシュを読むため、前のブランチの PR は表示しない
- 前回の取得の試行から次の間隔が過ぎていたら、バックグラウンドで取得を起動する。今回の描画は待たず、結果は次回以降の描画に反映される

| 状態 | 再取得の間隔 |
| --- | --- |
| open / draft で CI が実行中、またはローカルの HEAD が PR の head と違う | 30 秒 |
| open / draft で上に当たらない | 300 秒 |
| PR がない | 300 秒 |
| merged / closed | 900 秒 |
| 前回の試行が失敗した、またはキャッシュがない (2 回目以降の試行) | 300 秒 |

- 間隔と `PR_STALE_SEC` は内部定数で、conf からは変えられない
- ローカルの HEAD と PR の head が一致するかは取得の時点で判定する。描画は HEAD を見ないため、merged / closed の PR は、同じブランチに新しいコミットを積んでも次の再取得 (最大 900 秒後) まで表示が残る
- 取得の実行中は次の取得を起動しない。実行中の印が 90 秒より古いときは、異常終了の跡として消してから起動する
- 1 回の `gh` は 60 秒で打ち切る。失敗 (非ゼロ終了、打ち切り、想定外の出力) したときはキャッシュを書き換えず、前回の表示を残す
- 1 回の問い合わせの GraphQL のコストは 1 ポイント。最も短い 30 秒間隔が続くと、キャッシュ 1 つあたり 1 時間に最大 120 回になる
- 認証などの入力を求めない (`GH_PROMPT_DISABLED=1` と、[バックグラウンド fetch](#バックグラウンド-fetch-git_fetch1) と同じ git 用の 4 つ)。更新通知も出さない (`GH_NO_UPDATE_NOTIFIER=1`、`GH_NO_EXTENSION_UPDATE_NOTIFIER=1`)
- `GH_REPO`、`GH_FORCE_TTY`、`CLICOLOR_FORCE` は `gh` に渡さない。`GH_TOKEN`、`GITHUB_TOKEN`、`GH_HOST`、`GH_ENTERPRISE_TOKEN` はそのまま渡す

## 起動時チェックとフォールバック出力

必要なものが揃っていないときは、次の 1 行だけを出して終了する (終了コード 0)。

| 版 | 条件 | 出力 |
| --- | --- | --- |
| macOS 版 | `jq` が無い | `✻ -- (jq required: brew install jq)` |

| Linux 版 | `flock` が無い | `✻ -- (flock required: sudo apt install util-linux)` |

両版とも冒頭で `LC_ALL=C.UTF-8` を固定する。文字数の数え方と UTF-8 文字 (`✻`、`▁..█`、`…`、`↑↓`、`∙`) の表示はこれを前提にしている。

## 非目標

- **1 行構成へ戻す設定は設けない**。1 行目が出ないのは、1 行目の要素がすべて空のときだけ
- PR の状態表示では GitLab の merge request を扱わない
- Claude Code 標準のフッターの PR バッジは消さない (PR の状態表示とは別の場所に並んで表示される)
- 表示幅に基づくトリム (CJK を 2 桁として数える) は行わない
- 描画のたびに同期的に `git fetch` することはしない
- ctx の履歴チャートは持たない
- `HISTORY_LEN` は変更できない
- 設定ファイルを JSON や YAML にはしない (シェルの変数代入のみ)
